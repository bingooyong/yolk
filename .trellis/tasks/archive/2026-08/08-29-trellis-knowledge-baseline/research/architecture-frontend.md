# Research: Architecture, engine/game/frontend module map, and data flow

- Query: Audit Yolk Rush architecture, module ownership, router/state/audio/input/native boundaries, simulation and state flow, high-risk modules, historical constraints, and technical debt.
- Scope: internal
- Date: 2026-08-29

## Findings

### Evidence baseline

- `CONFIRMED` means directly visible in current repository code/config/docs/tests.
- `INFERRED` means supported by multiple current evidence points but not directly declared.
- `UNKNOWN` means the repository does not establish the fact.

Files audited include: `README.md`, `CLAUDE.md`, `AGENTS.md`, `package.json`, Vite configs, TypeScript config, `docs/**`, `.trellis/spec/frontend/*`, `src/routes/**`, `src/router.tsx`, `src/native-entry.tsx`, `src/components/**`, `src/engine/**`, and `src/game/**`. `README.md:1-19` identifies the product and build/dev commands; `CLAUDE.md:35-146` is the most complete architecture/constraint document.

### 1. Product and target shape — CONFIRMED

Yolk Rush is a Chinese-first 3D egg party obstacle race for iPhone/iPad. `README.md:1-19` and `CLAUDE.md:5-10` describe the gameplay, iOS Xcode shell, and web preview. The browser app is a full-screen React/R3F game, not a conventional page application: `src/routes/index.tsx:4-11` mounts `GameApp` in a `100dvh` main element, and `src/styles.css:46-56,70-77` disables document scrolling and touch selection around `.game-root`.

### 2. Two entries converge on one `GameApp` — CONFIRMED

- Web: `src/router.tsx:1-7` creates a TanStack router from generated `routeTree`; `src/routes/__root.tsx:45-56` provides the HTML shell, `AuthProvider`, and `PreviewHostBridge`; `src/routes/index.tsx:4-10` mounts `GameApp`.
- iOS/native Vite bundle: `src/native-entry.tsx:1-6` directly mounts `GameApp` into `#root`.
- `src/components/GameApp.tsx:45-58` is the shared app composition point: lazy `GameCanvas`, optional perf overlay, `MusicDirector`, `GameUI`, and `TouchControls`.
- `vite.native.config.ts:6-22` uses root `native/`, alias `@ -> src`, public assets, relative base, and output `native/ios/YolkRush/www`.
- `CLAUDE.md:37-46` documents the dual web/iOS paths. The statement that the web config “excludes” the native entry is architecture-effective, but the exclusion is not an explicit Vite `exclude` array in `vite.config.ts`; it is supported by the separate native root and web router entry graph.

### 3. Router/native ownership — CONFIRMED

- `src/routeTree.gen.ts:1-9` explicitly marks itself generated by TanStack Router and not editable.
- Current routing has exactly one path, `/`: generated route types only list `/` at `src/routeTree.gen.ts:20-37`, and `src/routes/` contains only `__root.tsx` and `index.tsx`.
- The web root owns document metadata, PWA manifest links, Chinese locale, auth provider, and preview bridge (`src/routes/__root.tsx:6-56`). The native entry owns none of those responsibilities and only loads global CSS plus `GameApp` (`src/native-entry.tsx:1-6`).
- The preview host integration is web-only: `src/components/preview-host-bridge.tsx:1-25` is mounted in `__root.tsx`, not by `native-entry.tsx`.

### 4. iOS shell is a local static WebView, not a feature bridge — CONFIRMED

`native/ios/YolkRush/YolkRushApp.swift:25-63` creates a WKWebView, registers a custom `yolkrush` scheme, allows JavaScript/mobile content, disables scrolling gestures, and loads `yolkrush://game/index.html`. The scheme handler serves files from bundled `www/` with MIME headers at `native/ios/YolkRush/YolkRushApp.swift:65-103,107-121`.

No `WKScriptMessageHandler`, `messageHandlers`, or native JavaScript bridge was found in the native source. Therefore, the confirmed “native bridge” is only local resource serving. Web preview communication is separate: `src/lib/preview-host-bridge.ts` uses `postMessage`; it is not mounted in the iOS entry.

### 6. Core simulation flow — CONFIRMED

1. UI invokes `startRace`. `store.startRace` selects the active level, clears moving-platform velocity through `setActiveLevel`, resets shared sim state, sets `coinsTotal`, advances `raceId`, and enters countdown (`src/game/store.ts:344-358`; `src/game/levels.ts:741-752`).
2. Countdown is UI-timed every 900 ms and calls `go()` to enter `playing` (`src/components/GameUI.tsx:74-90`).
3. `GameCanvas.Scene` mounts Rapier with gravity `-28`, fixed `PHYSICS_DT`, interpolation, and pause tied to store phase (`src/game/GameCanvas.tsx:44-52`).
4. `RacerField` creates one player plus level-defined bots and keys every racer by `raceId` (`src/game/EggRacer.tsx:933-980`).
5. Each racer runs in `useBeforePhysicsStep`: player input or AI waypoint intent, abilities, velocity/gravity, wind, Rapier character-controller collision, surface semantics, hazards, racer bumping, pickup/finish/fall handling, then writes kinematic position and mirrors state into `sim` (`src/game/EggRacer.tsx:243-326,340-439,439-550,587-719`).
6. Track kinematics use the same fixed-step hook. Movers calculate velocity with `PHYSICS_DT`; hammers/spinners/pendulums rotate from accumulated fixed-step time; dropping traps accumulate fixed time (`src/game/Track.tsx:157-188,239-274,276-385`).
7. Player finish directly calls `onPlayerFinish`; store computes placement reward, race coins, first/no-fall/perfect bonuses, XP, cleared state, best time, persists the result, and enters `results` (`src/game/EggRacer.tsx:615-622`; `src/game/store.ts:452-496`).
8. Fixed gameplay is deliberately separated from render interpolation. `src/engine/pipeline.ts:1-8` says input → AI wish → actions → controller → hazards → checkpoints → sim, with gameplay not in `useFrame`; `docs/visual/rendering-pipeline.md:3-9` repeats the frame contract.

### 7. Input and control-flow coupling — CONFIRMED / INFERRED

- `installInput` registers keyboard events, clears keys on blur, prevents game-key defaults, and lets Escape toggle pause/resume (`src/game/input.ts:48-121`).
- `pollInput` combines injected test keys, keyboard, touch, and gamepads; applies deadzones/clamping; derives pressed/released edges; and writes the global `actions` object (`src/game/input.ts:123-233`).
- Touch UI writes directly to the `touch` singleton: joystick move values at `src/components/TouchControls.tsx:42-77`, look deltas at `116-149`, and action hold/cancel state at `199-231`.
- Camera consumes look input, writes `sim.lookYaw`, `sim.lookPitch`, and derives `sim.camYaw` (`src/game/CameraRig.tsx:36-49,104-107`). Player movement uses `sim.camYaw` as its camera-relative movement basis (`src/game/EggRacer.tsx:264-274`).
- `CONFIRMED`: input data and camera-authored `camYaw` cross the render/physics boundary through mutable shared `sim`. `INFERRED`: this is intentional third-person control framing rather than accidental camera logic, but it means camera/input changes can alter movement semantics even though docs describe camera work as non-gameplay (`docs/visual/camera-system.md:3-13`).

### 8. State flow and persistence — CONFIRMED

The app has two distinct global state families:

1. **Zustand store (`useGameStore`)** owns phase, selected identity/level, durable progression/economy/settings, transient result/gacha state, and a throttled HUD projection (`src/game/store.ts:179-247,249-282,423-518`).
2. **`sim` singleton** owns live, non-React race data: time, trauma, camera/control state, taken pickups, racer mirrors, move state, failure hints, and pad HUD state (`src/game/sim.ts:48-102`).

State flow:

- `GameApp` initializes deterministic store defaults, then reconciles saved browser state only after mount (`src/game/store.ts:132`; `src/components/GameApp.tsx:38-43`).
- `store.pullSim` derives HUD racers, progress, time, place, coin count, and active failure hint from `sim` (`src/game/store.ts:423-450`).
- Durable fields are persisted to `localStorage`; schema is v4 with v3/v2/v1 read fallback (`src/game/store.ts:52,79-130`).
- `CLAUDE.md:139-146` explicitly requires a new v5 key for future schema changes rather than mutating v4 in place.
- `src/game/store-hydration.test.ts:70-99` locks deterministic first render, post-mount reconciliation, and continued v4 writes.
- Sequential unlock is derived from `LEVEL_ORDER` and `cleared`; the first level is always unlocked (`src/game/store.ts:301-306`).
- Gacha/economy values come from `skins.ts`: 80-coin cost, 25-coin duplicate refund, rarity weights, and placement rewards (`src/game/skins.ts:29-38,53-76`).

### 9. Rendering and visual data flow — CONFIRMED

`GameCanvas` resolves quality from explicit setting or device profile, gets immutable/remountable visual settings, applies theme background/fog, mounts lighting/camera/performance bridge/HUD pump, and lazily mounts the physics scene (`src/game/GameCanvas.tsx:64-115`).

Stable contracts:

- 60 Hz physics and 0.1 maximum render delta clamp (`src/engine/pipeline.ts:6-8`; `src/game/CameraRig.tsx:24-27`).
- ACES tone mapping, 1.18 exposure, sRGB output, camera near/far, and sky radius are centralized in `VISUAL_FOUNDATION` (`src/engine/visualProfile.ts:9-53`; applied by `GameCanvas.tsx:87-104`).
- Low/medium/high profiles control DPR, MSAA, shadows, shadow-map allocation, and environment map size (`src/engine/visualProfile.ts:55-95`).
- Crossing the no-MSAA/MSAA boundary remounts the canvas; medium→high does not (`src/engine/visualProfile.ts:101-108`; test at `src/engine/visualProfile.test.ts:30-37`).
- Lighting follows the player but keeps stable light direction and only the key light casts shadows (`src/game/LightingSystem.tsx:46-115`; `docs/visual/lighting-system.md:3-19`).
- Character presentation is transform-only and does not change controller bounds/contact (`src/game/character-presentation.ts:4-23,132-218`; focused test at `src/game/character-presentation.test.ts:33-87`).
- Level definitions compile AI waypoints and coin counts; presentation remains separate from collision definitions (`src/game/levels.ts:86-128`; `docs/visual/visual-architecture.md:5-16`).

### 10. Audio flow — CONFIRMED

`audio.ts` owns a browser-only WebAudio singleton with master/music/duck/SFX buses and two crossfading music slots (`src/game/audio.ts:97-180`). Tracks are three-layer loops; low-quality devices skip the high layer (`src/game/audio.ts:16-76,229-255`). State maps levels to BGM (`src/game/audio.ts:84-93`), and playback handles crossfade, intensity, stingers, pause ducking, and visibility (`src/game/audio.ts:317-440`).

`MusicDirector` is the store-to-audio adapter: user gesture unlock, visibility suspend/resume, volume/mute propagation, phase/level track selection, and progress-based intensity (`src/game/MusicDirector.tsx:16-85`). Gameplay/UI modules call specific SFX functions directly. Audio is therefore event-driven from both React state and physics/UI side effects.

### 11. Native/mobile constraints — CONFIRMED / UNKNOWN

- `Info.plist` enables full screen, hides status bar, supports portrait/landscape (all iPad orientations), and requests 120 Hz on iPhone through `CADisableMinimumFrameDurationOnPhone` (`native/ios/YolkRush/Info.plist:27-57`).
- Native fonts are loaded from Google Fonts (`native/index.html:14-19`), while game code/assets are local. Offline font behavior and exact native GPU performance are `UNKNOWN`; no physical-device evidence is recorded (`docs/visual/performance-guide.md:15-30`).
- Haptic UI calls `navigator.vibrate` (`src/engine/haptics.ts:3-9`), but the code itself notes iOS Safari support is generally absent, and the native shell exposes no haptics bridge. `CONFIRMED`: current haptic path is best-effort web API; `INFERRED`: real Core Haptics feedback is unavailable on iOS.
- Safe-area behavior is pervasive in root UI, hub, controls, and result screens (for example `src/components/GameUI.tsx:94-99`; `src/components/Hub.tsx:64-100`; `src/components/TouchControls.tsx:20-30`; `src/components/ResultScreen.tsx:51-56`).

### 12. High-frequency and high-risk modules — CONFIRMED

Runtime hot/risk concentration:

1. `src/game/EggRacer.tsx` — 995 lines; every racer runs controller, intent, abilities, collisions, hazards, pickups, finish, presentation sync, and sim writes in fixed physics steps (`wc -l`; `src/game/EggRacer.tsx:243-719`).
2. `src/game/Track.tsx` — collision semantics and all moving hazards; wrong fixed-step timing changes gameplay (`src/game/Track.tsx:98-155,157-385`).
3. `src/game/store.ts` — lifecycle, durable economy, save migration, and result correctness (`src/game/store.ts:29-130,344-399,423-518`).
4. `src/game/GameCanvas.tsx` / `CameraRig.tsx` — renderer remounting, frame hooks, HUD/ranking, and control-relative camera state (`src/game/GameCanvas.tsx:18-52`; `src/game/CameraRig.tsx:24-107`).
5. `src/game/audio.ts` — singleton lifecycle, media unlock, layering, and pausing (`src/game/audio.ts:97-180,273-440`).
6. `src/components/TouchControls.tsx` — pointer ownership, touch state, and direct-DOM high-frequency pad feedback (`src/components/TouchControls.tsx:35-149,152-231`).
7. `src/game/Level1BenchmarkArt.tsx` and `level1-benchmark.ts` — large repeated visual workload; tests enforce deterministic placement, platform alignment, and total instances (`docs/visual/environment-art.md:11-26`; `src/game/level1-benchmark.test.ts:8-94`).

No dedicated automated tests were found for `EggRacer` movement/controller behavior, hazard resolution, race ranking, audio lifecycle, touch controls, or gacha/economy. This is a `CONFIRMED` gap from current test inventory, not proof that behavior is broken.

### 13. Technical debt and boundary inconsistencies — CONFIRMED

- **Reverse engine dependency:** `src/engine/haptics.ts:1-6` imports game store. This makes `engine/` not independently reusable and contradicts the conceptual “cross-scene tools” ownership in `CLAUDE.md:66`.
- **Render-hook gameplay metadata:** `GameCanvas.Ranker` sorts racers and mutates `sim.racers[*].place` in `useFrame` (`src/game/GameCanvas.tsx:18-31`). Result victory depends on `player.place` (`src/game/store.ts:452-462`). This creates a physics/render ordering risk at finish even though normal movement obeys the fixed pipeline.
- **HUD sampler mismatch:** `HudPump` calls `pullSim` whenever `Math.floor(clock.elapsedTime * 12) % 2 === 0` (`src/game/GameCanvas.tsx:35-41`). That is a half-duty-cycle test, not an edge-triggered 12 Hz sampler; it can call repeatedly during the “on” phase. Documentation describes approximately 12 Hz sampling (`src/engine/pipeline.ts:4`; `docs/visual/rendering-pipeline.md:8`).
- **Input listener cleanup gap:** `installInput` adds an anonymous `document.visibilitychange` listener (`src/game/input.ts:112-114`) but cleanup removes only key/blur listeners (`116-120`). Repeated `GameApp` mount/unmount can leak listeners.
- **Dead/legacy UI branch:** `GameUI` still defines unused `TitleSheet` and legacy `Results` implementations (`src/components/GameUI.tsx:285-369,669-748`); current title/results use `Hub` and `ResultScreen` (`162`, `195-207`). The historical audit explicitly calls out a legacy presentation branch and mixed language (`docs/visual/visual-architecture-audit.md:19,36,65`).
- **Global mutable runtime state:** `sim`, `actions`, `touch`, active level, mover velocity, audio singleton, and texture caches are module globals (`src/game/sim.ts:71`; `src/game/input.ts:4-46`; `src/game/levels.ts:741-748`; `src/game/audio.ts:104-121`; `src/game/look.ts:3-9`). This simplifies hot paths but assumes one game instance and makes lifecycle/reset ownership critical.
- **Race time is player-gated:** only the player branch increments `sim.time`, and only while playing and unfinished (`src/game/EggRacer.tsx:696-719`). Bot finish times can therefore stop advancing after player completion. Current result UX usually exits immediately, but this ordering is a latent race-semantics debt.
- **Unused Drei dependency:** visual audit names Drei as installed but unused (`docs/visual/visual-architecture-audit.md:5`), and no `@react-three/drei` product import was found. The package remains in dependencies (`package.json:51`). This is dependency weight, not a runtime defect.
- `course.ts` is only a re-export of selected `levels.ts` APIs (`src/game/course.ts:1-12`), suggesting a historical import-path compatibility facade; most current modules import through it, but the compatibility reason is `UNKNOWN`.

### 14. Historical constraints that must survive refactors — CONFIRMED

- Preserve save compatibility: read v4/v3/v2/v1, write v4; future schema changes require v5 (`src/game/store.ts:52,79-130`; `CLAUDE.md:139-146`).
- Preserve deterministic SSR/first-render hydration: defaults first, `localStorage` reconciliation only after mount (`src/game/store-hydration.test.ts:70-99`; `.trellis/spec/frontend/visual-rendering.md:33`).
- Preserve fixed-step kinematics; the prior audit records movers/hazards mutating Rapier transforms at render rate as a fixed defect (`docs/visual/visual-architecture-audit.md:15`; current fixed-step code in `src/game/Track.tsx:243-385`).
- Preserve MSAA-aware canvas remounting (`src/engine/visualProfile.ts:101-108`).
- Keep the camera-following sky inside the camera frustum (`src/engine/visualProfile.ts:19-23`; test `src/engine/visualProfile.test.ts:39-41`).
- Keep original procedural assets/music only; no copied commercial characters/UI/textures/soundtracks (`docs/visual/visual-style-guide.md:3-6`; `docs/audio/music-manifest.md:1-7`).
- Keep the dev server host/port `0.0.0.0:8080` (`vite.config.ts:145-153`; `CLAUDE.md:139-145`).
- Do not hand-edit `src/routeTree.gen.ts` (`src/routeTree.gen.ts:7-9`).
- Visual/gameplay work has explicit validation gates: `npm run test:visual`, typecheck, lint/build, and browser visual smoke (`package.json:18-25`; `.trellis/spec/frontend/visual-rendering.md:53-63`).

### 15. Testing and validation map — CONFIRMED

`package.json:20` keeps the general test command focused on script tests plus app-data/auth tests. `package.json:24-25` defines a separate visual suite and smoke command. Current focused frontend/game tests cover visual tiers/remount/sky/tone, character contact/presentation, deterministic Level 1 layout/instancing, and store hydration (`src/engine/visualProfile.test.ts`; `src/game/character-presentation.test.ts`; `src/game/level1-benchmark.test.ts`; `src/game/store-hydration.test.ts`).

Historical validation evidence says broad lint/test suites had unrelated failures, while the focused visual path was used as the practical gate (`docs/visual/performance-guide.md:3-13`; `docs/visual/visual-architecture-audit.md:82-91`). Current pass/fail state was not rerun in this read-only research.
